# ALogin 外部身份绑定实现说明

## 当前闭环

```text
Geyser + Floodgate
    ↓ 读取 XUID
ALoginTransfer 扩展
    ↓ 签发短期 HMAC 断言并写入 Cookie
Minestom ALogin
    ↓ 校验签名、受众、有效期、jti
account_identity
    ↓ 命中绑定
Sa-Token + 原有 Cookie / Transfer
```

当前实现默认关闭。Geyser 使用 Bedrock 专用密钥，ALogin 的 `bedrock-shared-secret` 必须与其一致；Java 入口使用另一份 `java-shared-secret`。两份密钥均至少 32 个 UTF-8 字节，且不能提交到 Git。

未绑定的玩家先用原有密码登录，再执行：

```text
/identity bind
```

绑定关系使用 `provider + subject` 唯一约束：

- `BEDROCK_XUID` 使用 Floodgate XUID；
- `JAVA_MOJANG` 预留给 Velocity 认证适配器提供 Mojang Profile UUID；
- 不接受玩家客户端自报的 UUID、XUID 或名称作为认证依据。

## 配置

ALogin 配置：

```yaml
identity:
  enabled: false
  locale: "zh-CN"
  issuer: "ALogin"
  audience: "ALogin"
  java-shared-secret: ""
  bedrock-shared-secret: ""
  cookie-key: "alogin:identity"
  clock-skew-seconds: 15
  assertion-max-seconds: 60
```

Geyser 扩展首次启动生成的 `config.properties` 中，对应设置：

```properties
identity-enabled=true
identity-cookie-key=alogin:identity
identity-issuer=ALogin
identity-audience=ALogin
identity-shared-secret=与ALogin的bedrock-shared-secret相同的密钥
identity-assertion-ttl-seconds=60
```

`identity-issuer` 必须与 ALogin 的 `identity.issuer` 相同；`identity-audience` 和 Cookie 名称也必须一致。

## Java 适配器边界

本仓库包含可选的 `velocity-adapter` 模块，使用 LibreLogin 的公开 `AuthenticatedEvent` API：仅处理 `PREMIUM` 且 `Player.isOnlineMode()` 为真的事件，并使用 LibreLogin 提供的 Mojang Profile UUID 签发 `JAVA_MOJANG` 断言。它不读取认证插件私有数据库，也不按名称猜测正版身份。

Velocity 适配器首次启动会在插件数据目录生成 `config.properties`；只有配置了至少 32 个 UTF-8 字节的 `java-shared-secret` 后才启用。该密钥必须与 ALogin 的 `identity.java-shared-secret` 相同，且不能与 Bedrock 密钥复用。LibreLogin、Velocity 和 ALogin 需要部署在同一条 Java 入口链路上。

## 防重放与数据库

部署前执行 `app/src/main/resources/SQL/mysql/account_identity.sql` 和 `identity_assertion_replay.sql`。`identity_assertion_replay.jti` 使用唯一约束，断言消费记录进入共享数据库后，多个 ALogin 节点可以共同拒绝重复断言；过期记录会由登录请求按时间间隔清理。
